PlayFab bills by usage, so smart design keeps your costs low. Before you launch, review meter consumption on the **Billing Summary** in Game Manager and plan around the six main meters: Events, Profile, Content & Configuration, CloudScript, Insights, and Multiplayer Services.

For a full meter breakdown, see [Meters](/playfab/pricing/meters/overview).

## Events

Two types of events count against different meters:

- **PlayStream events** — processed by PlayStream (Actions, User Segmentation). Some are auto-generated.
- **Telemetry events** — sent straight to the data warehouse. Cheaper — roughly half the overage cost of PlayStream. Only generated by your title.

Both are billed in 1 KB blocks against average event size.

**Ways to cut cost:**

- Send only the fields you need. Smaller payloads = fewer meter ticks.
- Route offline-only analytics to Telemetry, not PlayStream.
- Turn off optional auto-events in **Settings → Data Collection**.
- Disable "generate PlayStream event" for CloudScript in production; re-enable only for debugging.

## Profile

Profile covers player data, entity profiles, characters, groups, and inventory. Since every player action can touch these meters, they usually need the most planning.

Billing is driven by data size and call frequency. Each 1 KB counts as one meter tick.

<Tip>
  Writing 10 keys × 100 bytes = 10 write ticks (each key writes at a 1 KB minimum). Reading those same 10 keys = 1 read tick (batched into a single response).
</Tip>

### Data and statistics

- Pack data tight — use enums, IDs, binary, bitfields.
- Batch reads. Batch writes when you can.
- Treat every service call as a real cost, not just a latency hit.

### Cheat protection

Don't over-secure. Match your write frequency to the actual risk.

- **Low-security games** (ad-monetized, no leaderboards) — trust the client, review events after the fact.
- **Round-based games** — aggregate per-round data and validate in CloudScript at session end.
- **Real-time games** — use hosted game servers as the authority. Update PlayFab state at session end or every few minutes.

If you're calling CloudScript more than a few times per minute per player, a hosted game server is likely cheaper.

### Data timeliness

Don't write every state change. Instead:

- Heartbeat updates every 15 minutes.
- Force an immediate write on significant player actions (purchases, level-ups).
- Stretch the heartbeat when the player is idle.
- If you add a manual "save now" button, throttle it on the client.

### Cross-player data

- Use [Leaderboards](/playfab/community/leaderboards) with [Profile View Constraints](/playfab/community/leaderboards/tournaments-leaderboards/using-the-profile-for-advanced-leaderboards) to bulk-fetch other players' info in a single call.
- Don't iterate leaderboard entries to fetch more per player — costs explode.
- For interactive sessions, only fetch data for the specific opponents involved.

## Economy and inventory

Treat inventory as **finite** inventory. If a resource updates hundreds of times per session (idle-game currency, ammo counts), model it as User Data, not inventory items.

**For real inventory:**

- Use **stackables** — one instance with a count is cheaper than N instances.
- Aggregate updates over a session or period.
- Prefer `ModifyItemUses` over add/remove cycles for stack changes.
- For [drop tables](/playfab/economy-monetization/economy/tutorials/drop-tables), batch "open N" or "open all" flows through CloudScript. Use `GetRandomResultTables` or `EvaluateRandomResultTable` to pre-compute results before touching inventory.

## Content and configuration

Covers title-level configuration: Title Data, Push Notifications, email, Title News, Entity Files, and CDN URL requests.

- Reads and storage bill by data size (in blocks larger than 1 KB).
- Writes bill per operation.
- CDN gigabyte transfer is billed separately — see [Content Delivery Network](/playfab/data-analytics/legacy/content-delivery-network).

**Ways to cut cost:**

- Use Entity Files for large per-player saves — usually cheaper than key-value patterns.
- Cache Title Data inside CloudScript VMs via static variables. Reload periodically to stay fresh.
- For CloudScript, consider hard-coding rarely-changing config directly into the script.

## CloudScript

Billed in GB-seconds, with a minimum of 128 MB and 100 ms per execution. Total executions are also metered.

- Batch actions when you can. Prefer one script call over many.
- If you're calling CloudScript many times per minute per player, a hosted game server is usually cheaper.
- Any Profile / Content & Config API you call from inside a script adds meter usage on top of the CloudScript cost.

## Insights

Covers all analytics — ingestion, storage, Event History, Data Explorer.

- Control retention in **Insights Management** in Game Manager.
- Set the performance level to match how much querying your analytics team does.

See [What is PlayFab Insights](/playfab/data-analytics/legacy/insights/overview) and [Insights best practices](/playfab/data-analytics/legacy/insights/best-practices).

## Multiplayer services

[Multiplayer Servers](/playfab/multiplayer/servers) and [Party](/playfab/multiplayer/networking) bill by usage.

**Multiplayer Servers:**

- Optimize how many concurrent players fit on a single core.
- Use the [QOS service](/playfab/multiplayer/servers/using-qos-beacons-to-measure-player-latency-to-azure) to place players smartly.
- Set minimum player thresholds before spinning servers up in low-population regions.

## Manage a live game

Once you're live, the biggest levers are analytics and player re-engagement. Target LiveOps campaigns to **narrow, well-defined segments** — this keeps operations fast and cheap.

Example: re-engagement based on last-sign-in windows (3, 7, 21 days). Use a Scheduled Task on a one-hour window per segment to send messages and grant items only to lapsed players who match.

## Summary

Every feature has a cost. Ask, for each requirement: does the player really need real-time accuracy, or is a few minutes of lag fine? For most games without real-time competition, batched updates on a heartbeat are cheaper and just as good. For real-time multiplayer, put the authority on a hosted server and only sync to PlayFab at the end of a session.
