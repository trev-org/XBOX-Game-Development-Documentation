PlayFab Multiplayer Servers (internally "Thunderhead") is a hosted game-server platform that runs your **authoritative game server binary** on Azure VMs, auto-scaling to demand. It handles the ops — image builds, region deployment, VM lifecycle, region failover, crash dumps — so you focus on the game.

## When to use Multiplayer Servers

Use hosted servers when:

- Your game is cheat-sensitive and needs server-authoritative simulation.
- You need dedicated per-match server processes (competitive shooters, MMOs, physics-heavy games).
- You want P95 latency guarantees per region and can't tolerate host-migration on peer-to-peer.

Use peer-to-peer or listen-server ([Party](/playfab/party)) when session count is small, latency is less critical, and the game logic can live on the host client.

## Concepts

## GSDK — the Game Server SDK

Your server binary integrates with PlayFab through the **Game Server SDK (GSDK)**. GSDK provides:

- `readyForPlayers()` — tell PlayFab this process is ready to receive an allocation.
- `getInitialPlayers()` — the list of expected players once allocated.
- `registerHealthCallback()` — return `Healthy` / `Unhealthy` so PlayFab can drain sick processes.
- `registerShutdownCallback()` — receive a graceful-shutdown signal (drain, save state, exit).
- `logMessage()` — archived to the build's log store.
- Region and session metadata for correlating server logs to matches.

GSDK ships for C\+\+, C#, Java, and Unity. Unreal titles get GSDK through the PlayFab Multiplayer OnlineSubsystem plugin.

## Authoring a build

<Steps>
  <Step title="Integrate GSDK">
    Add GSDK to your server project. Implement `readyForPlayers`, health, and shutdown callbacks.
  </Step>
  <Step title="Determine required DLLs">
    On Windows, run the `DetermineRequiredDlls` tool over your binary so the container image is complete.
  </Step>
  <Step title="Package">
    Package your binary as a Windows-container ZIP or a Linux container image. Include an entrypoint script that starts the server and any sidecars.
  </Step>
  <Step title="Create a build">
    In Game Manager → **Multiplayer → Servers → Builds → New build**. Upload the package or point at a container registry. Configure VM size, region list, per-VM process count, and startup script.
  </Step>
  <Step title="Deploy build regions">
    Roll the build out to your chosen regions. Set standby counts per region so the first match doesn't cold-start a VM.
  </Step>
  <Step title="Allocate and connect">
    Your matchmaking layer (or CloudScript) calls `RequestMultiplayerServer` to allocate a specific build in a specific region. Clients receive the IP \+ port in the allocation response.
  </Step>
</Steps>

## Scaling

Standby modes let you pre-warm capacity:

- **Scaling Standby** — target N standby VMs; when standby drops below the target, VMs spin up.
- **Dynamic Standby** — target based on a formula (e.g., 20% of current active \+ 5). Good for predictable diurnal patterns.
- **Scheduled Standby** — pre-declared curves per region per day — higher standby for weekend evenings, lower overnight.
- **Scaling Programmatically** — set standby via API for event-driven ramps.

Combine with **Build alias** to shift traffic between build versions during a rollout.

## Operational features

- **VM startup script (preview)** — custom PowerShell / bash run once per VM before the first process starts. Use for machine-scoped setup (registry keys, DDX enablement, cert install).
- **Manage secrets (preview)** — inject secrets into the server process at start time without baking them into the image.
- **OS patch level updates for Windows** — control which Windows base image your VMs run on.
- **Archive server logs** — every server process's stdout / stderr / GSDK log is archived and downloadable per session.
- **Quality of Service (QoS) beacons** — clients ping regional beacons to pick the lowest-latency region before allocating.

## Costs

Billing is per-VM-hour by size, plus egress. See **Multiplayer Servers billing** in Game Manager and the [multiplayer servers detailed price sheet](https://playfab.com/mps-detailed-pricing/). Reserve capacity discounts are available for predictable baselines. Development titles have a free monthly quota.
