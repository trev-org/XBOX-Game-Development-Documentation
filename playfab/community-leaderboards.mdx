Community **Leaderboards** rank players (or groups, or any entity type) by a score. On Learn's information architecture, Leaderboards live under **Community** rather than under Player Progression because they're a social artifact — people compare themselves against friends, guildmates, and cohorts, not against the raw stat.

See [Leaderboards & stats](/playfab/leaderboards-stats) for the progression-side view, including when to use PlayFab leaderboards vs. XBOX-native leaderboards.

## Leaderboard basics

A leaderboard has:

- A **key** (name).
- A **score column** — int, double, or DateTime.
- A **direction** — higher-is-better (kills) or lower-is-better (lap time).
- Optional **secondary columns** — ties broken by column 2, then column 3, etc.
- **Version increment policy** — manual, or scheduled (daily / weekly / monthly / seasonal).
- **Reset policy** — what happens to old data when the version increments (kept read-only, dropped, archived).

```cpp
// Write your score
UpdateEntityLeaderboardEntriesRequest req;
req.LeaderboardName = "weekly_kills";
EntityLeaderboardEntryUpdate entry;
entry.Entity = localEntity;
entry.Scores = { 42 };
req.Entries.Add(entry);
PlayFabLeaderboardsAPI::UpdateLeaderboardEntries(req, /* ok */, /* err */, nullptr);
```

## Community-scoped variants

What makes leaderboards a **Community** feature is that most useful leaderboards are scoped, not global. PlayFab supports:

### Seasonal leaderboards

Auto-increment the version on a schedule (weekly, monthly, or per season). The previous version is preserved for historical viewing.

Good for competitive ladders where you want a fresh start every cycle.

### Group leaderboards

Leaderboards can be filtered to the caller's group (guild, clan, party). Same underlying leaderboard — different visibility slice:

- "Top kills this week (my guild only)"
- "Fastest speedrun (across my friends)"

Use `GetLeaderboardAroundEntity` with a `GroupId` filter.

### Manual tiers

Divide players into tiers (Bronze, Silver, Gold, ...) with manual promotion / demotion at version increment. Better than pure score sort for competitive titles because players are ranked against near-skill peers.

### Stat-linked leaderboards

A leaderboard can be **linked to a statistic** — every stat update automatically updates the leaderboard. No separate write required; keeps the two in sync.

## Metadata columns

Attach small blobs of metadata per entry — loadout, level completed, replay ID. Metadata is returned in queries so a scoreboard UI can show more than just the score.

```cpp
entry.Metadata = R"({ "weapon": "railgun", "replay": "abc-123" })";
```

## Reading a leaderboard

The canonical read patterns:

- `GetLeaderboard` — the top N globally.
- `GetLeaderboardAroundEntity` — the caller's position with K entries above and below.
- `GetLeaderboardForEntities` — ranks for a specific list of players (friends slice, group slice).

## PlayStream and telemetry integration

Leaderboard updates emit PlayStream events. Route them through **Actions & Rules** to celebrate milestones (grant a reward when a player first breaks the top 100) or into **Telemetry** for post-season analysis.

## Limits and quotas

Each title has quotas on total leaderboards, entries per leaderboard, writes per second, and reads per second. Consult the Game Manager → **Leaderboards → Limits / Quota** pages before you design something extreme (a per-hour reset with a million active writers).

## Best practices

- **Prefer entity leaderboards** (v2) over legacy leaderboards for new titles.
- **Batch writes.** `UpdateLeaderboardEntries` takes an array — one call per session end beats one call per kill.
- **Design for cheat resistance.** Score writes should originate on a trusted surface — game server, CloudScript, or a signed telemetry event.
- **Archive seasons.** Keep the top 100 of every past season for player pride and historical analytics.
- **Consider XBOX-native for shell-visible leaderboards.** If a leaderboard must appear inside the XBOX guide, use XSAPI leaderboards; PlayFab leaderboards drive in-game UI.

## Deprecated: Tournaments & Leaderboards

The older Tournaments & Leaderboards service is deprecated. New titles should use entity Leaderboards. Existing titles can continue running Tournaments until you migrate.
