<Note>
  Economy v2 is the current, actively developed platform. Economy v1 (Legacy) is feature-frozen \\u2014 don't start new titles on it. If you're on v1, plan a migration.
</Note>

PlayFab Economy v2 is the recommended back end for any in-game economy your title runs outside of the Microsoft Store — soft currencies, crafting materials, character unlocks, time-limited drops, and the player inventory itself. It complements (rather than replaces) the Microsoft Store: Store transactions handle real-money payment and platform entitlements; Economy v2 models everything that happens **after** the player owns the game.

## Core concepts

## Querying a player's inventory

From the client, call `GetInventoryItems` with a PlayFab login token (see [Identity](/playfab/identity)):

```cpp
PlayFab::EconomyModels::FGetInventoryItemsRequest request;
request.Count = 100;
request.Filter = "";  // OData filter, optional

PlayFab::UEconomyAPI::GetInventoryItems(request,
    [](const PlayFab::EconomyModels::FGetInventoryItemsResponse& resp) {
        for (const auto& item : resp.Items) {
            // resp.Items contains item Id, quantity, stack metadata
        }
    },
    [](const PlayFab::FPlayFabCppError& err) {
        // handle error
    });
```

## Granting items

For anything that affects a player's balance — quest rewards, in-game purchase fulfillment, daily login bonuses — grant from a **server-authoritative** context, not the client. Either:

1. Use a CloudScript / Azure Functions handler with a server entity token.
2. Use a trusted game server with the title secret.

Granting from the client opens your economy to trivial exploitation.

```cpp
// CloudScript handler (TypeScript)
await economyApi.AddInventoryItems({
    Entity: { Id: playerEntityId, Type: "title_player_account" },
    Item: { Id: "gold_coin" },
    Amount: 100
});
```

## Connecting Economy to Microsoft Store purchases

When the player buys a hard-currency pack on the Microsoft Store, your title fulfills the in-game soft currency by:

1. Verifying the purchase via [XStore](/publishing/xstore-deep-dive) and Microsoft.StoreServices.
2. Calling Economy from a trusted back end to grant the corresponding soft-currency bundle.
3. Marking the consumable purchase as fulfilled with `XStoreReportConsumableFulfillment`.

See [Store Integration](/playfab/microsoft-store) for the full pattern.

## Rewarded ads

PlayFab supports **rewarded ads** as a monetization channel orthogonal to in-app purchase. The flow is:

1. The title requests an ad through the PlayFab rewarded-ads SDK, passing a placement identifier configured in Game Manager.
2. The ad SDK plays the ad and, on completion, calls PlayFab to validate.
3. PlayFab grants the configured reward (currency, consumable, XP) to the player inventory.

Rewarded ads are usually a poor fit for premium console titles but can be the right model for free-to-play companion or mobile builds. Configure placements per-title in Game Manager, and gate every reward grant through the server-side validation step — never trust a client claim that the ad played.

## Inventory patterns to know

- **Collections** \\u2014 a player may have several parallel inventories (main, storage, mailbox). Each collection has its own items and currencies.
- **Stacks** \\u2014 an item with `StackId` groups occurrences with shared metadata (durability, enchantment). Same item, different stacks = different rows.
- **ETags** \\u2014 every inventory operation returns an ETag. Pass it back on the next write to prevent lost updates during concurrent grants.
- **Transaction history** \\u2014 every write appends to a queryable history for auditing and player-support workflows.
- **TurboLoading** \\u2014 an opt-in mode that batches inventory reads to reduce round trips for large inventories.

## Player-segmented monetization

Use segments to change what a player sees:

- **Targeted offers** \\u2014 a starter pack visible only to players with less than one purchase.
- **Segment actions** \\u2014 auto-grant a comeback bundle when a lapsed player returns.
- **Store overrides** \\u2014 price a store item differently per country or LTV cohort.

Set these up in Game Manager under **Economy \\u2192 Player-segmented monetization**.
