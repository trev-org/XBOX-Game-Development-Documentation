Each queue defines:

- **Min/Max/Optimal players** — target match size.
- **Rules** — constraints applied to combinations of tickets.
- **Expansion** — how rules widen over time.
- **Ticket timeout** — how long an unmatched ticket lives.
- **Server capacity hints** — optional signals for allocation.

## Best practices

- Start with one rule, ship, then add rules based on data.
- Set expansion so long-waiting players eventually match, even in imperfect groupings.
- Keep timeouts short in playtests; longer in production to allow rule expansion.
