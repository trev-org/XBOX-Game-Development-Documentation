## Send a custom event

From the client, log a typed event:

```cpp
PlayFab::EventsModels::FWriteEventsRequest req;
PlayFab::EventsModels::FEventContents evt;
evt.Name = "level_complete";
evt.OriginalTimestamp = FDateTime::UtcNow();
evt.Payload = R"({
    "level": "caverns_2",
    "durationSeconds": 142,
    "deaths": 3,
    "completed": true
})";
req.Events.Add(evt);

PlayFab::UEventsAPI::WriteEvents(req,
    [](const auto&) { /* success */ },
    [](const auto& err) { /* handle */ });
```

For authoritative metrics (revenue, fraud-sensitive flags), log from a trusted server instead of the client.

## Event schema design

A few rules of thumb:

- **One event = one player action.** Don't batch unrelated payloads into a single event — you can't decompose them later in SQL.
- **Stable property names.** Insights treats `levelDurationSeconds` and `LevelDurationSeconds` as different columns.
- **Include identifiers.** Player entity ID, session ID, build version, and platform belong on every event for slicing.
- **Use numeric types for numbers.** Strings like `"142"` are painful to aggregate.

## PlayStream vs. Telemetry Keys

PlayFab has two ingest paths:

- **PlayStream** — authenticated events tied to a specific PlayFab entity. Requires a signed-in player or a title-secret-authenticated server. Best for player-attributable events (`level_complete`, `purchase`, `match_end`).
- **Telemetry Keys** — lightweight, high-volume, unauthenticated ingest for events that don't need to be tied to a specific player at write time (client crash reports, boot-time metrics, marketing pings). Cheaper per event.

A typical live title uses both. See [Telemetry Keys](/playfab/telemetry-keys) for the ingest-key model, session events, and per-key throttling.

## Querying with Insights

Insights exposes a Kusto-compatible query interface over your event stream. Build dashboards for:

- DAU / MAU and retention curves
- Funnel conversion through tutorial and onboarding
- Average revenue per paying user (ARPPU)
- Crash and error rate by build
- Matchmaking time and queue health

Pin queries to the PlayFab Game Manager dashboard so the whole team sees the same KPIs.

## Segmentation

Define **segments** — named filters over player attributes — to power targeted live ops:

- New players (created in last 7 days)
- High-value spenders (lifetime spend \> \$50)
- Lapsed players (last login \> 30 days ago)

Segments drive A/B experiments, push notifications, and economy-side promotions.

## Combining with XBOX telemetry

XBOX event-based stats and achievements live in the XBOX services pipeline, not in PlayFab. If you need both — say, XBOX achievement counts joined to PlayFab revenue — export PlayFab events to your own data warehouse and join there. Avoid trying to query XBOX stats from inside Insights.

## Learning from your data

Beyond raw KQL in Insights, PlayFab ships three higher-level surfaces:

- **Reports** — prebuilt daily / monthly reports (KPI, retention, top items, top spenders, CDN usage, A/B test KPI).
- **Trends** — time-series dashboards with segments as a dimension (preview).
- **Player Churn Prediction** — ML-backed per-player churn scores you can segment and dashboard on.
- **Microsoft Fabric real-time analytics** — live event stream into Fabric for enterprise BI and joining with non-PlayFab data.

## Privacy and compliance

PlayFab supports GDPR / CCPA workflows: right-to-delete via `DeleteMasterPlayerAccount`, GDPR export API, and Data Connections that can be configured with per-event redaction rules. Instrument privacy events themselves as PlayStream so you have a per-title audit trail.
