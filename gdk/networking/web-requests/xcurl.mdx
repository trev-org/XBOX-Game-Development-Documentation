**xCurl** is a Microsoft Game Development Kit (GDK)-compliant implementation of the [libCurl](https://curl.haxx.se/libcurl/) APIs. xCurl simplifies title development by adhering to all security requirements and best practices automatically — no special title logic required. It doesn't support WebSocket communication; for WebSockets use [libHttpClient](/gdk/networking/web-requests/overview#libhttpclient) instead.

xCurl is implemented on top of [WinHTTP](/gdk/networking/web-requests/winhttp) and automatically follows GDK requirements including Process Lifetime Management (PLM). While xCurl is API compatible with libCurl, its transport layer uses WinHTTP exclusively and does not use libCurl. xCurl therefore isn't required to stay in sync with the open-source libCurl (bug fixes, version numbers, etc.). You can use xCurl to maintain a single libCurl-style HTTP implementation across all platforms while changing only one header include and library linkage.

Several libCurl APIs aren't implemented in xCurl because they aren't commonly used in game development scenarios or don't have equivalent functionality in WinHTTP.

<Note>
  xCurl relies on the Gaming Runtime and can't be initialized until [XGameRuntimeInitialize](/reference/system/xgameruntimeinit/functions/xgameruntimeinitialize) is called.
</Note>

See the [libCurl API documentation](https://curl.haxx.se/libcurl/c/) for how xCurl methods work.

<Note>
  xCurl and WinHTTP implementations work on both Windows PC and Xbox console with no code changes required.
</Note>

## Developer support

xCurl is powered by WinHTTP, not libCurl, and is part of the GDK. Send support requests via your Microsoft representative or the Xbox Developer Forums.

## Add xCurl to your project

<Steps>
  <Step title="Install the GRDK">
    Ensure the Gaming Runtime Development Kit (GRDK) is installed on your development PC.
  </Step>
  <Step title="Reference the extension SDK">
    Open your `.vcxproj` and add the following. This links the import library and includes `xCurl.dll` with the build output.

    ```xml
    <GDKExtLibNames>Xbox.xCurl.API</GDKExtLibNames>
    ```
  </Step>
  <Step title="Update the header include">
    Replace `curl.h` with `xCurl.h`:

    ```cpp
    #include <xCurl.h>
    ```
  </Step>
</Steps>

## Configuration

xCurl is equivalent to libCurl compiled with:

- `HTTP_ONLY`
- `CURL_NO_OLDIES`
- `CURL_DISABLE_PROXY`
- `CURL_DISABLE_COOKIES`
- `CURL_DISABLE_DOH`
- `CURL_DISABLE_PROGRESS_METER`
- `CURL_DISABLE_MIME`
- `USE_SCHANNEL`

## Network initialization

xCurl handles [network initialization](/gdk/networking/initialization) automatically. Set up and issue requests at any point in your title's lifecycle — requests started before the network is initialized are queued and issued at the earliest opportunity.

## Suspend and resume

xCurl handles suspend/resume automatically.

- On suspend, all outstanding requests are canceled immediately and fail with `CURLE_NO_CONNECTION_AVAILABLE`. `curl_easy_getinfo(CURLINFO_OS_ERRNO)` returns `HRESULT_FROM_WIN32(PROCESS_SUSPEND_RESUME)` — useful if you want to distinguish this from a general network disconnect.
- All xCurl handles remain valid across suspend/resume — no cleanup or re-init needed.
- New requests started after suspend are held until resume \+ network initialization.

<Warning>
  When using the multi interface, keep calling `curl_multi_perform` (with optional `curl_multi_poll` or `curl_multi_wait`) on suspend while requests are outstanding. xCurl blocks suspend until in-progress requests complete — failing to call `curl_multi_perform` may cause your title to time out during suspend. Continue calling `curl_multi_perform` throughout the entire lifecycle regardless of suspend/resume state; xCurl handles the suspended-state details internally.
</Warning>

## Security

All HTTPS requests through xCurl follow the [communication security best practices (NDA)](/gdk-dev/game-principles/security/communication-security/communication-security-overview). xCurl automatically enforces any special certificate pinning specified in your title's Single Sign-on Portal. `CURLOPT_SSL_VERIFYPEER` cannot be used to disable certificate validation.

On devkits you may use the `http://` scheme for debug/test traffic. For **RETAIL** requests, you must use `https://`. Requests without a scheme default to `https`.

<Note>
  xCurl doesn't perform automatic token insertion. Retrieve Xbox Live tokens via `XUserGetTokenAndSignatureAsync` / `XUserGetTokenAndSignatureUtf16Async` and set them via `CURLOPT_HEADER`, `CURLOPT_HTTPHEADER`, or `CURLOPT_HEADERFUNCTION` before making the request.
</Note>

## Memory and concurrency

xCurl shares WinHTTP's concurrency limits: keep **concurrent requests to eight or fewer** across xCurl, WinHTTP, and Xbox Service APIs combined.

xCurl uses a flip buffer to receive data — higher throughput because it fills a second buffer while your title reads the first. If your read callback takes too long or `curl_multi_perform` isn't called frequently enough in multi mode, Winsock kernel memory can build up. See [socket memory considerations](/gdk/networking/game-mesh/winsock#socket-memory-considerations).

### Controlling xCurl allocations

By default xCurl uses the Windows heap and can be tracked via `XMemSetWin32HeapTrackingHooks`. Alternatively, provide memory functions at init time like libCurl does. In addition to [curl\_global\_init\_mem](https://curl.haxx.se/libcurl/c/curl_global_init_mem.html), xCurl provides the optional [xCurl\_global\_init\_mem](/reference/networking/xcurl/functions/xcurl_global_init_mem), whose callbacks match other GDK memory callbacks and provide more allocation info.

## Unsupported functionality

### Sockets and fd\_set

xCurl doesn't expose the underlying socket, so socket-level options and APIs — including `fd_set`–based `select`/`poll` — aren't implemented. Use `curl_multi_wait` and `curl_multi_poll` to wait for work.

Not present:

- `curl_easy_send`, `curl_easy_recv`
- `curl_multi_socket`, `curl_multi_socket_action`, `curl_multi_socket_all`
- `curl_multi_assign`, `curl_multi_fdset`

Have no effect and return `CURLE_NOT_BUILT_IN`:

- `CURLOPT_LOCALPORT`
- `CURLOPT_CONNECT_ONLY`
- `CURLOPT_SOCKOPTFUNCTION`, `CURLOPT_SOCKOPTDATA`
- `CURLOPT_OPENSOCKETFUNCTION`, `CURLOPT_OPENSOCKETDATA`
- `CURLOPT_CLOSESOCKETFUNCTION`, `CURLOPT_CLOSESOCKETDATA`
- `CURLOPT_XOAUTH2_BEARER`
- `CURLOPT_PROGRESSFUNCTION`, `CURLOPT_PROGRESSDATA`
- `CURLOPT_XFERINFOFUNCTION`, `CURLOPT_XFERINFODATA`
- `CURLOPT_NOPROGRESS`
- `CURLINFO_LASTSOCKET`, `CURLINFO_ACTIVESOCKET`
- `CURLMOPT_SOCKETFUNCTION`, `CURLMOPT_SOCKETDATA`
- `CURLMOPT_PIPELINING`
- `CURLMOPT_PUSHFUNCTION`

### CURL Share

The CURL Share interface is not implemented.

### Pause and resume transfers

Unsupported. Returning `CURL_WRITEFUNC_PAUSE` or `CURL_READFUNC_PAUSE` from a callback aborts the operation — you can't resume it.
