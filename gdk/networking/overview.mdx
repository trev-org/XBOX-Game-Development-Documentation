The networking stack and available APIs for Microsoft Game Development Kit (GDK) titles are similar to Win32 network APIs, which simplifies porting from existing Win32 titles and enables more unified network implementations.

## Available APIs

| Feature | API |
| --- | --- |
| All-in-one solution (network game data and in-game chat) | [PlayFab Party](/gdk/networking/game-mesh/playfab-party) |
| Secure client/server network game data transport | [MsQuic](/gdk/networking/game-mesh/msquic) |
| REST | [XSAPI](/services/xbox-live) |
| HTTP | [xCurl](/gdk/networking/web-requests/xcurl) or [WinHTTP](/gdk/networking/web-requests/winhttp) |
| WebSocket | [libHttpClient](/gdk/networking/web-requests/overview) (recommended) or [WinHTTP](/gdk/networking/web-requests/winhttp) |
| Sockets | [Winsock](/gdk/networking/game-mesh/winsock) |
| Socket security | OpenSSL DTLS or Bcrypt DTLS |
| Network connectivity | [XNetworkingGetConnectivityHint](/gdk/networking/initialization) |
| Port behavior | Identical to Win32 Windows PC (see [Winsock](/gdk/networking/game-mesh/winsock)) |
| In-game chat | [PlayFab Party](/gdk/networking/game-mesh/playfab-party) or [Game Chat 2](/services/multiplayer/game-chat-2) |

For guidance on choosing an HTTP or WebSocket API, see [Web requests](/gdk/networking/web-requests/overview).

## New and important concepts

Two concepts apply to almost every one of the GDK networking APIs.

### Network initialization

All networking APIs only function properly **once the network is initialized**. Your title should wait for network initialization before calling any networking API or middleware that relies on one. For details, see [Network initialization and connectivity](/gdk/networking/initialization).

<Warning>
  Calling `WinSock`, `WinHTTP`, `BCrypt`, `WinCrypt`, `schannel`, or `IPHLPAPI` before the network is initialized can produce unexpected failures, uninitialized return values, arbitrary packet loss, and even memory corruption.
</Warning>

### Suspend and resume

Almost all network handles and objects created from networking APIs must be **cleaned up during your title's suspend notification** and re-created on resume, after re-verifying network initialization. Each API overview describes what to do; both your title code and any middleware consuming these APIs must follow that guidance.
