XBOX Series consoles support hardware decompression for **zlib-compressed** content through DirectStorage. This article provides a **drop-in replacement for the stock software `inflate`** so you can add hardware decompression to an existing codebase with a minimum number of changes — immediate wins on decompression time and freed CPU for other work.

## One-time initialization

Create a memory-sourced, real-time DirectStorage queue and a status array once at startup:

```cpp Setup.cpp
Microsoft::WRL::ComPtr<IDStorageFactoryX>     inflateDropInFactory;
Microsoft::WRL::ComPtr<IDStorageQueueX>       inflateDropInQueue;
Microsoft::WRL::ComPtr<IDStorageStatusArrayX> inflateDropInStatus;

void CreateDSObjects()
{
    DX::ThrowIfFailed(DStorageGetFactory(
        __uuidof(IDStorageFactoryX),
        (void**)(inflateDropInFactory.ReleaseAndGetAddressOf())));

    DSTORAGE_QUEUE_DESC queueDesc = {};
    queueDesc.SourceType = DSTORAGE_REQUEST_SOURCE_MEMORY;
    queueDesc.Priority   = DSTORAGE_PRIORITY_REALTIME;
    queueDesc.Capacity   = DSTORAGE_MIN_QUEUE_CAPACITY;
    inflateDropInFactory->CreateQueue(
        &queueDesc,
        __uuidof(IDStorageQueueX),
        (void**)(inflateDropInQueue.ReleaseAndGetAddressOf()));

    inflateDropInFactory->CreateStatusArray(
        1, nullptr,
        __uuidof(IDStorageStatusArrayX),
        (void**)(inflateDropInStatus.ReleaseAndGetAddressOf()));
}
```

<Note>
  Memory-sourced DirectStorage queues **must** be created with real-time priority — that's why `DSTORAGE_PRIORITY_REALTIME` is set above.
</Note>

## Fallback and hand-off

Hardware decompression has a fixed per-job setup cost. For small buffers, software `inflate` is faster — the replacement falls back to software when:

- The output buffer is smaller than the compressed input (`avail_out <= total_in`), which indicates likely non-shrinking data.
- `flush != Z_FINISH` (multi-shot inflate is not supported by the drop-in).
- The output buffer is smaller than your profiled crossover threshold (`c_hardwareSizeCrossOverSize`).

Otherwise the call is routed to the hardware queue.

<Warning>
  This code assumes the compressed content conforms to [IETF RFC 1950](https://www.ietf.org/rfc/rfc1950.txt). See [Optimizing compressed content with DirectStorage and XBTC](/gdk/storage/directstorage/compression-xbtc) for details.
</Warning>

```cpp InflateDropIn.cpp
int inflateDropIn(z_streamp strm, int flush)
{
    bool fallback = false;
    if (strm->avail_out <= strm->total_in)                 fallback = true;
    if (flush != Z_FINISH)                                 fallback = true;
    if (strm->avail_out < c_hardwareSizeCrossOverSize)     fallback = true;
    if (fallback)
        return inflate(strm, flush);

    DSTORAGE_REQUEST request = {};
    request.Options.ZlibDecompress = true;
    request.Options.SourceType     = DSTORAGE_REQUEST_SOURCE_MEMORY;
    request.Source                 = strm->next_in;
    request.SourceSize             = strm->total_in;
    request.Destination            = strm->next_out;
    request.DestinationSize        = strm->avail_out;

    inflateDropInQueue->EnqueueRequest(&request);
    inflateDropInQueue->EnqueueStatus(inflateDropInStatus.Get(), 0);
    inflateDropInQueue->Submit();

    while (!inflateDropInStatus->IsComplete(0))
    {
        _mm_pause();
    }
    return Z_STREAM_END;
}
```

## Crossover timings

Measured on XBOX Series X|S at 3.8 GHz with ASCII text as the source buffer. **Block size in bytes, times in microseconds.** Your crossover point will differ with content type and compression ratio — **profile against your own data.**

| Block size | Software (CPU) | Hardware (MDU) |
| --- | --- | --- |
| 128 | 2.91 | 75.39 |
| 256 | 3.67 | 65.29 |
| 512 | 4.14 | 65.54 |
| 1,024 | 5.59 | 66.63 |
| 2,048 | 7.65 | 66.29 |
| 4,096 | 10.96 | 83.93 |
| 8,192 | 13.69 | 69.04 |
| 10,240 | 15.08 | 67.09 |
| 12,288 | 16.16 | 67.66 |
| 14,336 | 17.37 | 70.58 |
| 16,384 | 18.40 | 72.56 |
| 20,480 | 20.58 | 70.34 |
| 24,576 | 22.88 | 71.52 |
| 28,672 | 25.34 | 71.34 |
| 32,768 | 27.71 | 73.03 |
| 36,864 | 29.73 | 72.35 |

On ASCII text at 3.8 GHz, hardware overtakes software somewhere between **128 KiB and 256 KiB**. Highly compressible content will move the crossover in either direction — the point is to measure with your own workload.
