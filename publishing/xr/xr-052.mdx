## Intent

Customers expect saves to follow their account across consoles and across the family library. To make roaming work, the platform provides a save location the title must use. XR-052 requires titles to store user state in the platform save location — with defined dependencies on that state — rather than a title-owned location that won't roam.

## Applies to

Every title with per-user persistent state (single-player progression, unlocks, settings, campaign state).

## Requirement

Your title **MUST**:

- Store user state in the **Connected Storage** or equivalent platform-provided save location keyed to the signed-in XUID.
- Roam saves through Xbox network cloud save automatically.
- Handle **save conflicts** gracefully when a customer plays on multiple devices — present a conflict resolution UI, don't silently overwrite.
- Declare **save dependencies** so the platform can handle version migration correctly.
- Handle **corrupted saves** — detect corruption, present a clear message, offer to load a prior save or start fresh rather than crashing (see [XR-001](/publishing/xr/xr-001)).
- Handle **new account** state gracefully — first launch for a new customer must not error.
- Handle **account switching mid-session** — the current session's save state belongs to the previous account.

Your title **MUST NOT**:

- Store user state exclusively in a title-owned local file that doesn't roam.
- Silently overwrite the cloud save with a locally-modified save that may be older.
- Corrupt saves on a partial write (write-atomically: write to a temp file, fsync, rename).
- Persist save data past customer deletion of the entitlement.

## Tested scenarios

- Play on console A, save. Play on console B under the same account. Verify the save roams.
- Create a save conflict (play offline on A, offline on B, then reconnect). Verify the conflict resolution flow.
- Corrupt a save. Verify graceful detection and recovery.
- Sign out mid-session with unsaved progress. Verify handling.
- Switch accounts mid-session. Verify the new account gets its own state.

## Best practices

- Write saves **atomically** — write to a temp file, fsync, rename.
- **Version your save format** and support migration from older versions.
- **Test with slow / flaky cloud** — saves can take time to roam.
- **Don't gate progression on a save write completing** — the platform handles the async save; the title should acknowledge locally and let the platform sync.
