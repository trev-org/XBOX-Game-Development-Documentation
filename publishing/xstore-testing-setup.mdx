Most early XStore integration issues aren't code bugs — they're **configuration** issues. This page walks the setup that has to be right before XStore calls will return meaningful data.

For the high-level XStore modeling see [XStore deep dive](/publishing/xstore-deep-dive). For runtime PC quirks see [XStore on PC](/publishing/xstore-pc).

## Product testing setup (Partner Center \+ sandbox)

<Steps>
  <Step title="Create the product and add-ons in Partner Center">
    Every product you query via XStore must exist in Partner Center with a stable product ID. See [Create products](/publishing/how-to-create-products) and [Add-ons](/publishing/add-ons). Reserve the product IDs early — they can't be renamed after publish.
  </Step>
  <Step title="Publish the product to a dev sandbox">
    Products only surface through XStore in sandboxes where they're published. RETAIL is where customers see them; publish to your **dev sandbox** first so your test builds can query them. See [Sandboxes](/publishing/sandboxes) and [Sandboxes & test accounts](/publishing/how-to-sandboxes-test-accounts).
  </Step>
  <Step title="Fill in required metadata">
    Even a test-only product needs [Store listing](/publishing/store-listing), [Pricing](/publishing/pricing), and [Ratings](/publishing/ratings) to publish. Placeholders are fine for internal dev sandboxes but every field must validate green.
  </Step>
  <Step title="Update MicrosoftGame.config with the product identity">
    Your title's `MicrosoftGame.config` must reference the same TitleId, StoreId, and MSAAppId as the Partner Center product. Mismatches cause XStore calls to silently return empty results.
  </Step>
  <Step title="Point your devkit or PC at the dev sandbox">
    On console, use `xbconnect` or the XBOX Manager to switch sandbox. On PC, use the sandbox switcher documented in [XStore on PC](/publishing/xstore-pc). Sign in a test account provisioned for that sandbox.
  </Step>
</Steps>

## Licensing testing setup

Some XStore flows need a license to be present (or absent) in the sandbox before they behave correctly. Provision licenses on your test accounts to exercise each path.

### Test account license states you need

| State | Purpose |
| --- | --- |
| **Full license (owned)** | Retail-owner flow: trial-off, all DLC entitlements as configured on the account |
| **No license** | Store-page / purchase-prompt flows before any purchase |
| **Trial license** | Trial expiry and upsell flows |
| **Trial expired** | Post-expiry lock-out UI |
| **License lost mid-session** | `XStoreRegisterPackageLicenseLost` handler validation |
| **Family-shared license** | Product sharing model verification |
| **Game Pass license** | Game Pass-only feature flows |

### Provisioning licenses on a test account

<Steps>
  <Step title="Grant the product to the test account">
    In Partner Center, open the test account under **Sandboxes → Test accounts**. Grant the specific base game or add-on. This simulates a real purchase in the sandbox — no real money changes hands.
  </Step>
  <Step title="Acquire trials through the Store UI">
    Trial licenses can't be granted directly — sign the test account into the sandbox, open the Microsoft Store, and start the trial. This creates the trial license state your code needs to see.
  </Step>
  <Step title="Simulate a lost license">
    Revoke the entitlement on the test account in Partner Center; your title's next `XStoreRegisterPackageLicenseLost` callback should fire.
  </Step>
  <Step title="Simulate family sharing">
    Configure a family group across two test accounts in Xbox family settings; grant to the parent, sign in the child, and verify the family-share license appears.
  </Step>
</Steps>

### Mark-as-Provisioned for offline / pre-launch

Some flows — particularly disc-boot and offline pre-launch — require the product to be **Mark-as-Provisioned (MaP)** in the sandbox. MaP tells the platform to treat the product as installed and licensed without hitting the online license service. Enable MaP in your dev sandbox for the specific product you're testing offline scenarios against; disable it before promoting the sandbox state to RETAIL.

## Common misconfigurations

| Symptom | Root cause |
| --- | --- |
| `XStoreQueryProductsAsync` returns empty | Product not published to the active sandbox |
| Add-on shows unavailable in Store UI even though granted | Test account owns it in a different sandbox |
| Trial APIs return `isTrialOwnedByThisUser = false` | Trial not acquired through the Store UI on this account yet |
| Consumable purchase succeeds but balance never updates | `MicrosoftGame.config` StoreId doesn't match the Partner Center product |
| `XStoreShowPurchaseUIAsync` opens the wrong SKU | Product ID mismatch or the product isn't published in the current sandbox |
| PC XStore call fails with `E_GAMESTORE_NETWORK_ERROR` | PC sandbox switcher not pointing at the same sandbox as the devkit / dev account |
