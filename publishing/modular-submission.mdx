Partner Center uses a **modular submission** model. Rather than one monolithic "submit game" button, each **module** (Store listing, Packages, Pricing, Age ratings, Properties, Gaming metadata, XBOX services, etc.) can be edited and published independently.

## Why this matters

- Push a Store listing typo fix without recerting your packages.
- Drop a price for a weekend sale without touching anything else.
- Update packages for a patch without republishing Store presence.
- Or, gate a cross-module release (new SKU \+ new packages \+ new pricing) as a single coordinated submission.

## The Review and publish module

Every product has a top-level **Review and publish** module. It shows the current state of every other module and what will change if you publish now.

## What triggers certification

| Module changed | Requires cert? |
| --- | --- |
| Packages | Yes |
| Age ratings (with new IARC answers) | Yes |
| Properties that affect XR compliance | Usually |
| Store listing copy, screenshots, trailers | No — Store review only |
| Pricing | No — with propagation delay |
| Availability / visibility | No |
| XBOX services | No cert on publish; effect takes hold on sandbox promotion |

## Branches and modular submission

Module changes can live on a **branch** and publish independently of your Main branch. See [Branches](/publishing/branches).
