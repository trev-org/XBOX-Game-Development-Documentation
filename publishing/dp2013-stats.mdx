**Player stats** in DP 2013 are per-player numeric values (kills, distance traveled, high score, hours played). Stats are computed by **stat rules** that transform incoming events into stat updates.

## Anatomy of a stat

- **Stat ID** — short identifier queried at runtime.
- **Data type** — integer, double, or string.
- **Aggregation** — how new event values update the current value:
  - **Sum** — total kills, total distance.
  - **Max** — high score, longest streak.
  - **Min** — fastest time.
  - **Replace** — latest value only.
- **Featured** — whether it appears on the player's Xbox profile (see [Featured stats](/publishing/dp2013-featured-stats)).
- **Leaderboard** — whether it drives a leaderboard (see [Leaderboards](/publishing/dp2013-leaderboards)).

## Stat rules

A **stat rule** binds an event to a stat update:

- **Event source** — `PlayerKilled` from [Events](/publishing/dp2013-events).
- **Filter** (optional) — only apply the rule when `weaponType == "sniper"`.
- **Target stat** — `SniperKills`.
- **Update expression** — typically `stat += 1` or `stat = max(stat, event.score)`.

Rules run after events are ingested; stat updates are visible via the User Stats query API after the DP 2013 latency window.

## Authoring stats

<Steps>
  <Step title="Define events first">
    Stats depend on events. Author every event that will feed a stat before authoring the stat. See [Events](/publishing/dp2013-events).
  </Step>
  <Step title="Open the Stats editor">
    In Partner Center under Xbox services (DP 2013), open Stats.
  </Step>
  <Step title="Create the stat">
    Provide stat ID, data type, and aggregation.
  </Step>
  <Step title="Attach a stat rule">
    Bind an event to the stat with an update expression. Filter if needed.
  </Step>
  <Step title="Publish to sandbox and validate">
    Publish to your dev sandbox, emit test events from a test account, and confirm the stat updates via the User Stats query API.
  </Step>
</Steps>

## Constraints

- Stat ID is immutable once published — choose carefully.
- Data type changes require a versioned schema change and pipeline drain.
- Stats with very high update rates (per-frame writes) will overload the DP 2013 pipeline; batch or aggregate on the client.
